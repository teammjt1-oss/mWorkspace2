### 4.2 반응성: Vue → MobX

- 원본 클래스는 getter와 setter로 파생값을 만든다. MobX는 클래스의 getter를 그대로 `computed`로 만들 수 있어 모델 코드 모양을 유지하기 좋다.
- 대응
  - `reactive(state)` → `observable(state)`
  - `computed(() => …)` 필드 → 그냥 `get` getter (MobX가 캐시한다). 원본의 `_badges = computed(…)` 같은 우회도 getter로 줄인다.
  - `Ref<Dto[]>` → `observable.array`
  - `toValue(x)` → 필요 없어진다
  - 화면은 `mobx-react-lite`의 `observer`로 감싼다.
- 모델 서브클래스는 `makeObservable`을 매번 적지 않도록 기반 클래스에서 `makeAutoObservable` 계열로 한 번에 처리한다. 서브클래스의 필드 초기화 순서 문제가 있어서 **PR 1에서 가장 먼저 검증할 항목**이다.
- 의존성 추가: `mobx`, `mobx-react-lite` 2개. (PR 설명에 이유를 적는다.)

### 4.3 저장소 인스턴스: 전역 싱글턴 → Store

원본은 `model역할s.getInstance()`로 전역 싱글턴을 부르고, SSR 요청이 섞이지 않게 요청 스코프 캐시(`instance.ts`)와 payload 전달(`bindPayload`)을 따로 두었다.

- Next.js에서는 클라이언트 컴포넌트도 서버에서 한 번 렌더되므로, 모듈 전역 싱글턴은 요청끼리 데이터가 섞인다.
- 그래서 저장소를 **`Store` 객체 하나가 소유**한다.
  - `Store`는 클라이언트 Provider가 `useState`로 한 번 만든다. 서버 렌더에서는 요청마다, 브라우저에서는 탭마다 하나다.
  - 모델이 다른 표를 부를 때는 `getInstance()` 대신 `this.store.get(model메뉴s)`를 쓴다.
  - 계정이 바뀌면 `Store`를 통째로 새로 만든다. 원본의 `do전체repo초기화`와 `reset()`이 필요 없어진다.
  - 테스트는 테스트마다 새 `Store`를 만든다.
- 첫 데이터
  - 서버 컴포넌트가 DB에서 직접 행을 읽어 props로 넘기고, Provider가 `store.get(X).hydrate(rows)`로 받는다.
  - 원본의 `bindPayload`, `apiFetch잡기`, `useRequestFetch` 분기가 모두 없어진다.

### 4.4 행 식별자

원본은 서버가 PK를 매긴다. 그래서 저장 전 행을 가리키려고 `rowKey`(Symbol로 심은 `local:000001`)를 따로 두고, `hasServerPk`, `pksOf`("먼저 저장하세요"), 시드용 `시드PK` 등록부까지 생겼다.

이식본은 빈 DB로 시작하므로 PK 방식을 바꿀 수 있다.

- **결정: PK를 uuid로 하고 클라이언트가 만든다.** (`crypto.randomUUID()`)
  - 행은 태어날 때부터 PK가 있다. `rowKey`와 `stateId`가 같아진다.
  - 저장 전 여부는 `is신규` 플래그 하나로 판정한다(서버에서 받은 행 또는 저장 성공 시 `false`).
  - 없어지는 것: `BaseModels2.identity.ts` 대부분, `pending-`/`just_created`/`imsi` 자리표시자 판정, `createDraft`와 `create`의 이중 경로, 시드 `code` → PK 등록부.
  - 시드는 고정 uuid를 적어 서로 가리킬 수 있다.
  - 주의: 저장 전 행을 FK로 가리키는 관계 행은 여전히 부모를 먼저 저장해야 한다. 이 순서는 `do저장후에` 큐가 지금처럼 맡는다.
- 서버는 받은 uuid의 형식만 검사하고, 이미 있는 PK로 `POST`하면 409를 돌려준다.

### 4.5 저장과 부수효과 규칙 (부채 정리)

원본 부채 대부분이 "setter 안에서 저장하거나 confirm을 띄운다"에서 나온다. 엔진과 모델에 규칙을 둔다.

1. **setter는 값만 바꾼다.** 저장, confirm, 다른 표 수정을 하지 않는다.
   - 예: 역할의 `is기본옵션` setter → `do기본으로지정()` async 메서드로 옮긴다. 기존 기본 항목이 없어도 동작해야 한다.
2. **저장이 들어간 메서드는 `async`이고, 부르는 쪽은 반드시 `await`한다.** `@typescript-eslint/no-floating-promises`를 켜서 강제한다.
3. **엔진은 UI를 부르지 않는다.** `confirm`, `useAlert`, `useModalDragDrop`을 엔진과 모델에서 뺀다.
   - 엔진 메서드는 결과를 값으로 돌려주거나 던진다(`do저장`은 `boolean`, `do모두저장`은 `i저장결과`).
   - 확인 창과 알림은 뷰가 띄운다. 모델이 사용자 확인을 요구하는 동작은 버튼 스펙에 `confirm: '문구'`로 선언하고 뷰가 처리한다.
4. **Promise 생성자 안의 async를 쓰지 않는다.** 원본 `do저장`, `delete`, `create`의 `new Promise(async …)` 패턴을 평범한 `async` 함수로 바꾼다.
5. **서버로 보낼 필드는 스키마가 정한다.** 원본은 "한글 키와 `etcFields`를 뺀다"는 정규식으로 걸렀다. 이식본은 Drizzle 스키마의 열 목록만 보낸다. `etcFields`와 저장 후 한글 키 삭제가 없어진다.

### 4.6 타입과 Dto

- Dto는 Drizzle 스키마에서 뽑는다: `type i역할dto = typeof roles.$inferSelect`.
- 원본의 `any`(엔진 파일 약 36건)는 없앤다.
  - 기반 클래스의 `repo: BaseModels2<any, Dto, any>` → `BaseModels<BaseModel<Dto>, Dto>`
  - `i정렬조건.func`의 `(a: any, b: any)` → `i정렬조건<T>` 제네릭
  - `i필드.key`는 `keyof 모델 & string`으로 좁혀 오타를 컴파일 때 잡는다.
- 모델의 한글 getter 이름은 원본을 따른다. 사용자에게 보이는 문구가 아니라 코드 식별자지만, 원본과 대응시키기 위해 유지한다.

### 4.7 통신

- 엔진은 표 하나에 대해 아래 요청만 한다. 형태는 원본 `/api/v1/[table]`과 같게 둔다.

| 동작    | 요청                                    | 비고                            |
| ------- | --------------------------------------- | ------------------------------- |
| 목록    | `GET /api/t/{table}?omit=본문열`        | `본문열` 규칙 유지              |
| 한 행   | `GET /api/t/{table}/{id}`               | 상세에서 본문 채우기            |
| 추가    | `POST /api/t/{table}`, `POST …/bulk`    |                                 |
| 수정    | `PUT /api/t/{table}/{id}`, `PUT …/bulk` |                                 |
| 삭제    | `DELETE /api/t/{table}/{id}`            | 목록에서 먼저 빼고 실패 시 복구 |
| 표 버전 | `GET /api/t/versions`                   | 변경 번호 등록부                |

- 서버 액션 대신 route handler를 쓴다. 엔진 클래스가 fetch 한 곳만 알면 되고, 표 허용 목록·권한·zod 검증을 한 입구에서 할 수 있다. 서버 쪽 상세는 5절에서 쓴다.
- fetch 함수는 `Store`가 주입한다. 테스트에서는 가짜 fetch를 넣는다.
- 버전 확인은 "창에 포커스가 올 때 + 5초 간격"으로 한다(원본은 1초). 체감 차이가 있으면 줄인다.

### 4.8 큰 표 (1만 건)

신청, 회원게시글, 회원댓글은 전체를 받지 않는다.

- 저장소에 `읽기방식: '전체' | '페이지'`를 둔다. 기본은 `'전체'`다.
- `'페이지'`인 표는 같은 `i조회`(검색어, 정렬, 필터선택s)를 서버로 보내고, 서버가 SQL로 거른다. URL 쿼리 모양(`?q=`, `?sort=`, `?f_축=`)은 같다.
- 그래서 이 세 표의 필터 축은 JS `match` 대신 **열 기반 선언**(열, 연산, 값)으로 제한한다. 다른 표를 이어 붙여 계산하는 필터는 이 세 표에서 쓰지 않는다.
- 상세 규칙과 페이지 크기는 5·6절에서 정한다. 엔진은 두 방식의 인터페이스만 맞춘다.

### 4.11 검증

- 단위 테스트 (Vitest, 가짜 fetch)
  - `조회하기`, `조회쿼리` ↔ `쿼리조회` 왕복, `textSearch`: 원본 동작을 기준값으로 삼는다.
  - `is수정됨`: 값 변경, 큐, 신규 행, `do수정취소` 후 복귀
  - `do저장`: 신규는 POST, 기존은 PUT, 실패 시 상태 유지
  - `delete`: 실패 시 목록 복구
  - `do모두저장`: 건너뜀 사유와 부분 실패 결과
  - `hydrate` 후 재조회 때 모델 객체가 유지되는지(원본의 `Object.assign` 불변식)
  - 계층: 순환 데이터에서 `조상s`, `자손s`가 멈추는지
- 역할 모델 하나를 실제로 옮겨 `apps/admin`에서 목록, 상세, 저장까지 E2E로 확인한다(11절의 첫 단계).

## 5. 서버와 보안

원본 `base2/server`의 표 API(`/api/v1/[table]`, `api-guard`, `db_supabase`, `공개필드s`)를 옮긴다. 인증은 "스타터 구조 결정" 문서대로 Better Auth를 쓴다.

### 5.1 범위

| 대상                                     | 이 계획에서                                                                                      |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 표 CRUD (`/api/v1/[table]`)              | 옮긴다                                                                                           |
| 권한 판정 (`api-guard`, `공개필드s`)     | 옮기고 원본의 구멍을 막는다                                                                      |
| 표 버전 (`tables`, `bump_table_version`) | 옮긴다                                                                                           |
| 파일, 채점, 결제, AI, sitemap            | 옮기지 않는다. 모델이 필요로 할 때 따로 계획한다(파일은 Vercel Blob, 결제는 토스페이먼츠 recipe) |
| 개발 로그인                              | 스타터의 테스트 로그인 경로로 대체한다                                                           |

### 5.2 표 등록부: 한 곳에서 표를 선언한다

원본은 표 정보가 네 곳에 흩어져 있다. DB 표, `iDB테이블s`(권한 선택지), `model테이블s`(등록부 표), `공개필드sByTable`/`본인열ByTable`이다. 표를 추가할 때 하나라도 빠뜨리면 권한을 줄 수 없거나 조회가 깨진다.

이식본은 **서버 등록부 하나**에 모은다(`packages/base/server/등록부.ts`, `server-only`).

```ts
export const 등록부 = {
  roles: 표({
    table: roles, // Drizzle 표
    공개열s: ["id", "label", "icon"],
    본인열: null, // 행 주인을 가리키는 열
    본문열: null, // 목록에서 뺄 무거운 열
    읽기방식: "전체", // '전체' | '페이지' (4.8)
  }),
  // …
};
```

- URL의 `{table}`은 이 등록부의 키다. **등록부에 없는 이름은 404**다. 원본은 경로의 문자열을 그대로 Supabase에 넘겼다.
- 권한 선택지(역할 편집 화면)도 이 등록부의 키 × 액션으로 만든다. 등록부에 있는 표는 반드시 권한을 줄 수 있다.
- DB 표 이름은 snake_case(`member_posts`), 등록부 키와 권한 이름은 원본처럼 kebab-case(`member-posts`)로 둔다. 열은 Drizzle의 `casing: 'snake_case'`로 TS에서는 camelCase를 유지한다.

### 5.3 요청 처리 순서

모든 표 요청은 route handler(`apps/admin/src/app/api/t/[table]/…`) → `packages/base/server`의 함수 하나를 거친다. route handler는 얇게 두고, 순서는 한 곳에서 정한다.

1. **표 확인**: 등록부에 없으면 404
2. **요청자 확인**: Better Auth 세션 → 사용자 → 역할 코드. 비로그인은 401. 관리 앱은 로그인한 사용자만 쓴다 (5.5)
3. **권한 판정**: `{표}:{액션}` (5.4). 없으면 403
4. **입력 검증**: zod. 실패하면 400 (5.6)
5. **실행**: Drizzle, 요청 하나를 트랜잭션 하나로 (5.7)
6. **표 버전 올리기**: 같은 트랜잭션 안에서 (5.8)
7. **응답**: 공개 투영과 본인 범위를 적용한 행

- 서버 컴포넌트가 첫 데이터를 읽을 때(4.3의 hydrate)도 **같은 함수**를 부른다. DB를 직접 읽는 두 번째 길을 만들지 않는다. 권한 판정을 건너뛰는 경로가 생기기 쉬운 자리다.
- route handler는 `dynamic = 'force-dynamic'`으로 두고 Next 캐시를 쓰지 않는다. 캐시 판단은 표 버전이 한다.

### 5.4 권한 모델

권한 문자열 `{표}:{액션}`과 `roles.permissions` 배열은 원본 그대로 둔다. 액션의 뜻을 분명히 하고, 원본에서 선언만 있고 구현이 없던 것을 구현한다.

| 액션         | 뜻                                        | 원본                               |
| ------------ | ----------------------------------------- | ---------------------------------- |
| `read`       | 전체 행, 전체 열                          | 있음                               |
| `readPublic` | 전체 행, `공개열s`만                      | 있음                               |
| `readOwn`    | `본인열 = 요청자 회원 id`인 행만, 전체 열 | 선언만 있고 가드에 없음 → **구현** |
| `create`     | 추가                                      | 있음                               |
| `update`     | 전체 행 수정                              | 있음                               |
| `updateOwn`  | 본인 행만 수정                            | 없음 → **추가**                    |
| `delete`     | 전체 행 삭제                              | 있음                               |
| `deleteOwn`  | 본인 행만 삭제                            | 없음 → **추가**                    |

- 여러 읽기 권한이 있으면 넓은 쪽을 쓴다(`read` > `readOwn` > `readPublic`). `readOwn`과 `readPublic`을 함께 가지면 본인 행은 전체 열, 남의 행은 공개 열만 준다(원본 `투영본인`과 같다).
- `create`는 `본인열`이 있는 표에서 `create`만 있고 `update`가 없는 역할이면 **본인열을 서버가 요청자로 덮어쓴다.** 남의 이름으로 행을 만들지 못한다.
- `*Own` 판정은 SQL `where`에 넣는다. 읽은 뒤에 거르지 않는다.
- 역할 목록은 원본처럼 짧게(3초) 캐시한다. 같은 서버 인스턴스에서 `roles`를 쓰면 캐시를 바로 비운다.
- 원본의 `off`/`warn`/`enforce` 모드는 옮기지 않는다. 늘 `enforce`다.
- manager의 "내 담당만"은 표마다 범위 규칙이 필요하다. 등록부에 `범위: (요청자) => SQL 조건`을 둘 자리만 만들고, 회원 모델을 옮길 때(9절) 채운다.

**원본 보안 구멍과 이식본의 대응**

| 원본 구멍                                     | 이식본                                                                                              |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| 파일 업로드·삭제에 인증 없음                  | 파일 라우트는 이번 범위 밖(5.1). 옮길 때 표 API처럼 `요청자확인()`을 먼저 부르는 것을 규칙으로 둔다 |
| learner가 신청 전체를 읽음 (`readOwn` 미구현) | `enrolls:readOwn` 구현                                                                              |
| guest에게 `enrolls:update`, 행 주인 검사 없음 | 관리 앱에 비로그인 접근이 없다(5.5). 로그인한 사용자의 본인 행 수정은 `updateOwn`으로 한다          |
| manager "내 담당만"이 화면에서만 거름         | 등록부 `범위`로 서버에서 거름 (회원 모델 때)                                                        |
| 표 이름을 검사 없이 DB에 넘김                 | 등록부 허용 목록                                                                                    |
| 대량 수정이 트랜잭션 없이 한 행씩             | 요청 하나 = 트랜잭션 하나                                                                           |

### 5.5 인증

- **관리 앱은 로그인한 사용자만 쓴다.** (2026-09-24 결정) 비로그인 요청은 표 API에서 401, 화면에서는 로그인 페이지로 보낸다.
  - 원본 admin에서 비로그인 사용자(guest)가 쓰던 게시판 열람·신청 화면은 관리 앱으로 옮기지 않는다. 필요하면 공개 사이트(`apps/web`)가 서버 코드에서 따로 맡는다.
  - 따라서 관리 앱에는 guest 권한 판정과 익명 로그인이 없다. `guest` 역할 코드는 데이터로만 남는다.
  - 로그인한 learner도 쓰므로 `readPublic`과 `*Own`은 그대로 필요하다.
- Better Auth, 소셜 로그인(구글, 카카오). 스타터 구조 결정 문서의 규칙(인증된 이메일일 때만 계정 병합, 이메일에 unique를 걸지 않음)을 따른다.
- 역할은 원본처럼 토큰에 싣지 않는다. 요청마다 세션의 사용자 id로 `사용자-역할` 관계를 읽는다(3초 캐시와 함께). 역할을 바꾸면 다음 요청부터 바로 반영된다.
- 사용자와 회원의 연결(`users.memberId`)은 원본 구조를 유지한다. `*Own` 판정은 회원 id로 한다.
- 개발과 테스트: 스타터의 테스트 로그인 경로로 역할별 계정에 들어간다. 원본의 admin과 admin_manager 중복을 없애 **역할당 계정 하나**(guest 제외 3개)로 만든다.

### 5.6 입력 검증

- 등록부의 Drizzle 표에서 zod 스키마를 만든다(`drizzle-zod`의 `createInsertSchema`/`createUpdateSchema`). 의존성 추가이므로 PR에 이유를 적는다.
- 서버가 채우는 열(`createdAt`, `updatedAt`)은 입력 스키마에서 뺀다.
- **모르는 열이 오면 400**으로 거절한다(`strict`). 조용히 버리면 엔진 쪽 실수(4.5의 5번)가 드러나지 않는다.
- `id`는 uuid 형식만 받는다(4.4). 이미 있는 id로 `POST`하면 409.
- `bulk` 요청은 한 번에 500행까지. 넘으면 413.
- `?omit=`은 등록부 표의 실제 열 이름일 때만 받는다. 원본은 정규식으로만 검사했다.
- 모델별 추가 규칙(예: 역할 코드는 `guest|learner|manager|admin` 중 하나)은 등록부에 `검증: z.object(…)`로 덧붙인다. 클라이언트의 `beforeSave`와 별개로 서버가 최종 관문이다.

### 5.7 실행

- 모든 쓰기는 트랜잭션 안에서 한다. `bulk`는 전부 성공하거나 전부 실패한다. 원본은 한 행씩 따로 보내 중간 실패 시 일부만 저장됐다. 엔진의 `do모두저장` 결과(4.1)도 이 전제에 맞춘다.
- 목록 읽기 상한 10,000행은 원본대로 유지하고, 넘으면 자르지 않고 에러를 낸다. 원본 주석의 이유(잘린 목록은 에러 없이 틀린 화면이 된다)가 그대로 유효하다.
- `readPublic`은 SQL `select`에서 공개 열만 고른다. 받은 뒤 깎지 않는다.
- 응답은 쓰기 뒤의 전체 행을 돌려준다(원본과 같다. 엔진이 응답으로 상태를 덮는다).
- 에러 응답은 `{ message }` 한 모양이고, 문구는 한국어다. DB 에러 원문은 로그에만 남긴다.

### 5.8 표 버전

- 표 `table_versions(name, version)`을 두고, 쓰기가 성공할 때마다 그 표의 `version`을 1 올린다.
- 원본은 DB 트리거(`bump_table_version`)로 올렸다. 이식본은 **5.3의 6단계에서 앱 코드로 올린다.** (2026-09-24 결정)
  - 스타터는 `db:push`로 스키마를 반영한다. 트리거는 Drizzle 스키마로 표현되지 않아 별도 SQL 마이그레이션 흐름이 필요하다.
  - 대신 표 API를 거치지 않는 쓰기(다른 앱의 서버 코드, 수동 SQL)는 버전을 올리지 않는다. 서버 코드용 쓰기 함수를 `packages/base/server`에서 내보내고, 그 함수만 쓰도록 한다.
- `GET /api/t/versions`는 로그인한 사용자에게 모든 표의 번호를 준다.

### 5.9 큰 표의 서버 조회 (4.8의 서버 쪽)

`읽기방식: '페이지'`인 표(신청, 회원게시글, 회원댓글)는 같은 URL 쿼리를 SQL로 바꾼다.

| 쿼리       | SQL                                                                |
| ---------- | ------------------------------------------------------------------ |
| `?q=`      | 등록부에 선언한 `검색열s`에 `ILIKE`, 열끼리 OR                     |
| `?sort=`   | 등록부에 선언한 정렬 이름 → `order by` 열. 선언에 없으면 기본 정렬 |
| `?f_<축>=` | 등록부에 선언한 필터 축 → 열 조건(`eq`, `in`, `is null`, 범위)     |
| `?page=`   | `limit 50 offset …`. 응답은 `{ rows, total }`                      |

- 필터 축과 정렬은 모델(클라이언트)과 등록부(서버)가 **같은 선언을 공유**한다. 두 벌이면 칩과 결과가 갈린다. 선언은 순수 데이터로 `packages/base`의 공용 위치에 둔다.
- 권한의 `*Own`, `범위` 조건은 이 조회에도 똑같이 걸린다.
- 1만 건에서 `ILIKE`는 충분히 빠르다. 느려지면 `pg_trgm` 인덱스를 추가한다.

### 5.11 검증

- 단위 테스트
  - `권한.ts`: 역할 × 표 × 액션 행렬. 원본 구멍 네 가지가 막혔는지를 테스트 이름으로 남긴다.
  - zod 스키마: 모르는 열, 서버 열, 잘못된 uuid, 500행 초과
  - `조회SQL.ts`: 쿼리 → 조건 변환, 선언에 없는 정렬·필터 이름
- 통합 테스트 (로컬은 `pnpm db:up`, CI는 Postgres 서비스 컨테이너)
  - `bulk` 중간 실패 시 전체 롤백
  - 쓰기 후 표 버전 증가
  - `readOwn`/`updateOwn`이 남의 행에 닿지 않음
- E2E: 역할별 테스트 로그인으로 역할 표 목록·저장, 권한 없는 역할의 403 화면, 비로그인의 로그인 페이지 이동
- **CI에 Postgres를 띄운다.** (2026-09-24 결정) 지금 `.github/workflows/ci.yml`의 `check`와 `e2e` 작업에는 DB가 없고, `DATABASE_URL`은 env 검증용 값뿐이다.
  - 두 작업에 `services: postgres`(스타터 `docker-compose.yml`과 같은 이미지·계정)를 추가하고, 테스트 전에 `pnpm db:push`를 돌린다.
  - 통합 테스트는 `*.int.test.ts`로 구분해 DB가 없는 로컬에서도 `pnpm check`가 단위 테스트만으로 돌 수 있게 한다. CI에서는 둘 다 돈다.
  - 이 변경은 모델 이식과 별개인 스타터 변경이라 첫 PR 전에 따로 `chore/` PR로 낸다.

### 6.1 원본 구성

- 관리 페이지 25개가 모두 같은 모양이다.
  1. 권한을 확인하고, 없으면 `ViewAlert`를 띄운다.
  2. `do첫조회`로 주 표와 **의존 표**를 함께 읽는다. 예: 회원 화면은 메뉴, 회원이력, 역할, 등급까지 읽는다.
  3. `View목록5`에 저장소를 넘긴다.
- 페이지끼리 다른 점은 권한, 의존 표, `범위`(`own-members`의 "내 담당 회원"), `can추가`, `can삭제`뿐이다.
- 목록5가 하는 일
  - 머리: 메뉴 라벨, 정렬 선택, "모두 저장"(수정된 행 수 칩), 수정 모드 스위치
  - 필터줄: 축별 선택, 옵션별 건수, 걸러진 수/전체 수, 좁을 때 접히는 띠와 고른 칩
  - 목록: 보기 세 가지(목록, 가로카드, 세로카드), 계층 표는 드래그 트리(`mList2`), 끝의 "새 … 추가"
  - 바닥: 보기 선택, 검색창
  - 오른쪽 상세, 좁은 화면에서는 시트
  - 주소 동기: `?id=`, `?tab=`, `?q=`, `?sort=`, `?f_축=`
  - 상세에 들어갈 때 `본문열`을 한 행만 받고, 받는 동안 수정을 잠근다.
  - 칸 높이에 따라 카드를 줄로 내리고(보기 강등), 필터를 접는다.
- 상세와 `useModelForm`이 하는 일
  - 머리글: 사진이나 아이콘, 제목(연필로 수정), 부제, 뱃지, 머리로 올린 필드(`position: 'top'`)
  - 요약 타일(`요약s`), 좁으면 한 줄로 압축
  - 탭은 `자동필드ss`의 묶음이고, 탭마다 분할 비율(`config.ratio`)이 있다.
  - 필드 목록은 `폭`(반, 전체, 옆)으로 여러 열에 배치한다.
  - 필드마다 로딩 상태가 있고, 하나라도 로딩 중이면 목록이 선택 이동을 막는다.
  - 수정 모드에서 삭제 버튼

### 6.2 페이지 25개 → 화면 등록부

페이지 파일을 표마다 만들지 않고, 화면을 선언 한 줄로 등록한다.

```ts
// apps/admin/src/화면s.ts
export const 화면s = {
  roles: 화면({
    모델: model역할s,
    의존: [model회원s, model회원관계이력s, model회원상태이력s],
  }),
  "own-members": 화면({
    모델: model회원s,
    의존: [model회원이력s, model역할s, model등급s],
    범위: (회원, 나) => 회원.담당자id === 나.회원id,
    can: { 추가: false, 삭제: false },
  }),
};
```

- 라우트는 `apps/admin/src/app/(관리)/[screen]/page.tsx` 하나다.
  - 3절의 `[table]`을 **화면 키**로 받는다. `own-members`처럼 표가 아닌 화면이 있기 때문이다.
  - 주소는 원본 페이지 경로를 그대로 쓴다(`/roles`, `/own-members`).
  - 등록부에 없는 키는 404다.
- 서버 컴포넌트가 하는 일
  - 로그인과 `{표}:read` 권한을 확인한다. 없으면 403 화면을 보인다.
  - 주 표와 의존 표의 행을 읽는다. **5절의 `표API` 읽기 함수를 직접 부른다**(HTTP를 거치지 않음). 그래서 공개열, 본인 행, `범위` 규칙이 API와 한 곳에서 걸린다.
  - 요청자 정보(`나`: 회원 id, 역할)와 행을 클라이언트 Provider에 넘긴다. Provider는 `hydrate`로 받는다(4.3).
- 원본 `메뉴` 행이 주던 값(라벨, 세는단위, 빈 목록 문구, 계층 여부)은 **화면 선언의 기본값**으로 옮긴다.
  - 메뉴 모델을 옮긴 뒤에는 메뉴 행의 값이 기본값을 덮는다(9절).
  - 헤더에서 메뉴 라벨을 바로 고치던 기능은 없앤다. 메뉴 관리 화면에서 고친다.
- 의존 표는 명시적으로 선언한다. 모델 코드에서 자동으로 뽑지 않는다. 빠지면 조인 값이 빈칸으로 보이므로, E2E에서 화면마다 한 번씩 열어 확인한다.

### 6.3 상태의 주인

| 상태                                | 주인                                | 원본과 차이                                                                    |
| ----------------------------------- | ----------------------------------- | ------------------------------------------------------------------------------ |
| 검색어, 정렬, 필터선택, 선택 행, 탭 | **주소**(`useSearchParams`)         | 원본은 컴포넌트 상태와 주소를 양방향 watch로 맞췄다. 주소 하나를 정본으로 둔다 |
| 검색창 입력 중인 글자               | 목록 컴포넌트, 300ms 뒤 주소에 반영 |                                                                                |
| 수정 모드                           | 관리 레이아웃 context(앱 전역)      | 원본도 전역(`useMyAuthStore.is수정중`)                                         |
| 보기(목록, 카드)                    | 사용자별 브라우저 저장              | 원본은 메뉴 행에 저장해 모든 사용자가 공유                                     |
| 필드 로딩                           | 상세 컴포넌트, 필드 key별 `Map`     | 원본은 인덱스별 ref 배열이라 `splice` 충돌 우회가 있었다                       |
| 행 데이터                           | Store(4.3)                          |                                                                                |

- 주소를 바꿀 때는 `window.history.replaceState`/`pushState`를 쓴다. Next.js가 `useSearchParams`와 맞춰 주고, 서버 컴포넌트를 다시 요청하지 않는다. `router.replace`를 쓰면 글자를 칠 때마다 서버가 DB를 다시 읽는다.
- 원본의 주소 규칙은 유지한다.
  - 좁은 화면에서 상세를 **여는** 이동만 push, 나머지는 replace. 뒤로가기가 페이지를 떠나지 않고 상세를 닫는다.
  - 첫 탭, 묶음이 하나뿐인 행은 `?tab=`을 적지 않는다. 그 행에 없는 탭 이름이면 첫 탭을 연다.
  - 손으로 고른 행은 첫 탭에서 시작하고, 주소로 온 선택만 주소의 탭을 따른다.
  - `?id=`의 행이 검색어에 가려져 있으면 검색어를 한 번 비운다.
- 원본에서 없어지는 것: "저장되면 `local:*` 주소를 PK로 바꾸기"(uuid라 처음부터 같다, 4.4), `같은선택` 비교와 헛도는 v-model 방지.

### 6.5 상세

- 원본 규칙을 유지한다.
  - 머리글은 사진, 아이콘, 부제, 뱃지, 머리 필드 중 하나라도 있을 때만 세운다. 라벨뿐이면 아래 `이름` 필드와 겹친다.
  - 머리로 올린 필드는 아래 폼에서 뺀다. 버튼은 `position`으로, 값 필드는 key로 뺀다.
  - 요약 타일은 한 줄에 다 들어가지 않으면 띠로 압축한다(최소 폭 88px, 간격 8px).
  - 탭은 `show`가 참인 묶음만 보인다. 목록의 `?tab=` 판정과 같은 함수를 쓴다.
  - 버튼의 `is수정할때만`, 필드의 `canEdit`와 수정 모드, 권한으로 잠김을 정한다. 원본은 머리글과 폼이 같은 규칙을 두 곳에 적었다. 이식본은 `is잠김(필드, 수정모드, can)` 함수 하나로 둔다.
- 삭제는 뷰가 확인 창을 띄운 뒤 `await model.delete()`를 부른다(4.5 규칙 3). 성공하면 상세를 닫고 목록에 포커스를 준다.
- 버튼 스펙의 `confirm: '문구'`도 같은 확인 창으로 처리한다(4.5).
- 필드를 어떤 컴포넌트로 그리는지(`타입지정` → 컴포넌트), `폭`의 기본값 규칙(`기본폭`)은 7절에서 정한다.

### 6.6 큰 표 (4.8, 5.9의 화면 쪽)

`읽기방식: '페이지'` 표(신청, 회원게시글, 회원댓글)는 목록이 다르게 동작한다.

- 주소 조회 키에 `?page=`를 더한다. 목록 아래에 페이지 번호 줄을 둔다(50건씩). 검색, 정렬, 필터가 바뀌면 1쪽으로 돌아간다.
- 검색창은 300ms 뒤 요청하고, 앞선 요청은 취소한다(`AbortController`).
- 전체 수는 서버 응답의 `total`을 쓴다.
- **필터 옵션별 건수는 보이지 않는다.** 원본처럼 세려면 옵션마다 서버 집계가 필요하다. 1단계는 옵션 이름만 보이고, 필요하면 나중에 집계 요청을 추가한다.
- `?id=`의 행이 지금 쪽에 없으면(링크로 들어온 경우) 그 행만 `GET …/{id}`로 받아 상세를 연다.

## 7. Field 단계

원본 `base2/app/components/Field`(34개 파일, 4,437줄), 타입 → 컴포넌트 연결(`ORM.ts` 135줄, `ORM.resolve.client.ts`), 스펙 → 필드 변환(`View/1.ts` 476줄)을 옮긴다. 많이 쓰는 필드부터 만들고, 아직 없는 필드는 대체 표시로 버틴다.

### 7.1 원본 구성

- 모델이 `자동필드ss`에 필드 스펙을 적는다: `{ key, label, type: 타입지정.선택0, options, props, 폭, position, canEdit, show }`.
- 컴포넌트는 이 순서로 고른다.
  1. 스펙의 `type`
  2. `options`가 있으면 `선택0`
  3. 값의 타입: 불리언 → 체크, 문자 → 문자, 숫자 → 숫자, 배열 → 문자s, dayjs → 날짜, dayjs 쌍 → 기간
  4. 문자
- 필드 계약: `v-model`(값), `readonly`, 스펙의 `props`를 그대로 펼치고, 선택지는 `items`로 받는다. 버튼만 값 없이 `onClick`, `label`, `icon`을 받고, 누르는 동안 `isDoing`을 켠다.
- `기본폭`: 스펙에 `폭`이 없으면 컴포넌트 종류로 정한다. 카드, 카드s, 매트릭스, 본문, 선택s, 유튜브, 파일, 여러 줄 문자는 `'전체'`, 나머지는 `'반'`이다.
- 읽기 모드는 입력 상자의 테두리, 배경, 그림자만 벗기고 여백은 둔다(`_읽기base`). 모드를 바꿔도 값과 줄이 움직이지 않는다.
- `ORM.resolve.client.ts`는 `Field/` 폴더를 glob으로 훑어 이름 → 컴포넌트 표를 만든다. `View/1.ts` ↔ `Field/카드s.vue`가 서로를 import해서 첫 호출 때 표를 짓는 우회가 들어 있다.

### 7.2 필드 계약: Vue → React

모든 필드 컴포넌트는 같은 props를 받는다.

```ts
// packages/base/view/필드/계약.ts
export interface i필드Props<V> {
  value: V;
  onChange: (v: V) => void;
  readonly: boolean;
  items: readonly i선택항목[]; // 선택 계열만 쓴다
  props: Record<string, unknown>; // 스펙의 props. 필드마다 zod로 좁힌다
}
```

- `v-model` → `value`와 `onChange`. `onChange`는 모델 setter를 MobX `action`으로 부른다(`model[key] = v`). setter는 값만 바꾼다(4.5 규칙 1).
- 스펙의 `props`는 원본처럼 필드마다 다르다. 필드 컴포넌트가 자기 props 스키마를 zod로 선언하고, 맞지 않으면 개발 환경에서 경고하고 기본값을 쓴다. `Record<string, any>`를 펼치던 원본 방식은 `any` 금지 규칙에 걸린다.
- 버튼 필드는 `i버튼Props`(`label`, `icon`, `onClick`, `disabled`, `confirm`)를 따로 받는다. `onClick`이 Promise를 돌려주면 끝날 때까지 로딩을 보이고 다시 누르지 못하게 한다. `confirm`은 6.5의 확인 창으로 처리한다.
- 읽기 모드에서도 버튼은 눌린다(원본과 같다). 보일지는 `show`와 `is수정할때만`이 정한다.

### 7.3 타입지정과 컴포넌트 등록부

엔진은 React를 모른다(3절). 그래서 `타입지정`을 **이름만 가진 데이터**로 두고, 이름 → 컴포넌트 연결은 뷰가 한다.

```ts
// packages/base/engine/필드.ts: 모델이 import하는 쪽. 모양은 원본과 같다
export const 타입지정 = {
  선택0: { name: "선택0" },
  선택s: { name: "선택s" },
  버튼: { name: "버튼" },
  // …
  _: { 문자: { name: "문자" }, 숫자2: { name: "숫자2" } /* … */ },
} as const;

// packages/base/view/필드/등록부.ts: 뷰 쪽
export const 필드컴포넌트s: Partial<Record<i필드타입, ComponentType<i필드Props<unknown>>>> = {
  문자: Field문자,
  선택0: Field선택0,
  // 아직 없는 타입은 비워 둔다 → 7.8의 대체 표시
};
```

- 모델 코드는 `타입지정.선택0`, `타입지정._.문자`를 원본 그대로 쓴다. 줄 단위 대응(4.1)이 유지된다.
- glob 훑기와 순환 import 우회(`ORM.resolve.client.ts`)가 없어진다. 등록부는 명시적인 import 목록이다.
- 등록부는 `Partial`로 시작한다. 모든 타입을 채운 뒤(11절의 마지막 단계) `Record`로 바꿔 빠진 타입을 컴파일 때 잡는다.

### 7.4 스펙에서 필드로 (`View/1.ts`)

`get특정필드`가 하던 일을 **순수 함수**와 **컴포넌트 선택**으로 나눈다.

- `필드해석(model, spec)`(엔진, 순수): `{ key, label, 타입, 폭, props, items, canEdit, show, position, is한줄 }`를 돌려준다. 타입 결정 순서(7.1), `기본폭`, 버튼 판정이 여기 들어간다. React도 MobX 반응도 모르므로 단위 테스트로 원본 동작을 고정한다.
- 뷰는 해석 결과의 `타입`으로 등록부에서 컴포넌트를 꺼내고, 값은 렌더할 때 `model[key]`로 읽는다. `observer` 안에서 읽으므로 값이 바뀌면 그 필드만 다시 그린다.
- 원본의 `computed(() => …)` 스펙 값(`show`, `options`)은 **인자 없는 함수**로 쓴다: `show: () => this.stateCode !== 'guest'`. 뷰가 `observer` 안에서 불러 MobX가 추적한다. 4.2의 "computed 필드 → getter"와 같은 방향이다.
- `get상단필드s`(머리글로 올릴 필드, `label` 칸 찾기), `get버튼s`, `get승격버튼s`는 규칙을 그대로 옮기고 6.8의 `use상세필드.ts`가 부른다. `get행동버튼s`는 챗봇용이라 옮기지 않는다(6.4).
- 필드 한 줄의 틀(라벨, `is한줄`일 때 라벨과 입력을 한 줄에, 로딩 표시, 잠김)은 `필드.tsx` 하나가 그린다. 잠김은 6.5의 `is잠김` 함수를 쓴다.

### 7.5 날짜 값

원본 모델은 날짜를 dayjs 객체(`mDayjs`, 서울 시간대)로 주고받는다. 모델 18개 파일에서 155번 쓰고, `toDate`, `format`, `diff`, `startOf`를 주로 부른다.

- **결정: dayjs를 유지한다.** (2026-09-24) 엔진에 `mDayjs`(dayjs + `utc`, `timezone` 플러그인, 기본 `Asia/Seoul`)를 두고 모델은 원본처럼 import한다. 날짜 계산 줄을 고치지 않고 옮길 수 있다. 의존성 추가: `dayjs` 1개(플러그인은 포함).
  - 대안인 "문자열로 주고받고 모델이 필요할 때 변환"은 155곳을 고쳐야 하고, 옮기는 중에 날짜 계산이 틀리기 쉽다.
- DB 열은 Drizzle에서 `mode: 'string'`으로 읽는다. 모델 getter가 `mDayjs(this.state.x)`로 감싸고 setter가 문자열로 되돌린다(원본 `model회비.기준일`과 같은 모양).
  - `date` 열: `YYYY-MM-DD`
  - `timestamptz` 열: ISO 문자열. 날짜시간 필드는 입력값에 `+09:00`을 붙여 저장한다(원본 규칙).
- **입력 UI는 브라우저 기본 입력을 쓴다.** (2026-09-24 결정) 날짜는 `<input type="date">`, 날짜시간은 `<input type="datetime-local">`(원본 날짜시간 필드가 이미 이 방식이다).
  - shadcn `calendar`는 `react-day-picker`와 `date-fns`를 함께 들여온다. 기본 입력은 의존성이 없고 모바일에서 OS 선택기가 뜬다.
  - 달력 팝업의 모양이 브라우저마다 다르다. 필요하면 2단계에서 `calendar`를 추가한다.

### 7.10 검증

- 단위 테스트(Vitest)
  - `필드해석`: 타입 결정 순서(`type` → `options` → 값 타입 → 문자), 버튼 판정, `선택2` 별칭
  - `기본폭`: 전체 폭 타입, 여러 줄 문자, 스펙의 `폭`이 이기는지
  - `규칙.ts`: 선택지 수에 따른 표시 방식(5 / 6 / 21개 경계), 읽기 모드에서 고른 것만 남기기, 느슨한 비교(`1`과 `'1'`), 숫자2 입력 해석(숫자 아닌 글자 제거, 빈 값은 `null`, `min`/`max` 자르기), 날짜시간 `+09:00` 왕복
  - 스펙 `props` 스키마: 모르는 props에 경고하고 기본값을 쓰는지
  - 등록부에 없는 타입이 대체 표시로 가는지, 대체 표시가 `onChange`를 부르지 않는지
- E2E(Playwright)
  - 필드 견본 화면: 1차 11종을 수정 모드에서 값 바꾸기, 읽기 모드에서 입력 상자가 잠기고 줄 위치가 그대로인지
  - 역할 화면: 색상(알약), 기본값(선택), 소개(여러 줄), API 권한(여러 개 선택)을 바꿔 저장하고 새로고침 후 값 유지
  - 버튼 필드: 누르는 동안 다시 눌리지 않음, `confirm` 창의 취소
